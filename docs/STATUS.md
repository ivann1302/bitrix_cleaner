# Текущее состояние

Обновлено: 10 сентября 2026 года. Стадия: real read-only адаптер готов локально; проверка iframe/портала не запускалась.

## Готово

- Строгий React/TypeScript/Vite-каркас, mock-поиск, preview до 3 000 записей, пагинация и исключения.
- CSV выбранных строк всех страниц: UTF-8 BOM, кавычки/переносы/кириллица и нейтрализация формул. Это контрольный экспорт, не полный backup.
- Подтверждение неизменяемого набора ID, контекста и условий. Изменения выбора/фильтра аннулируют подтверждение; срок списка — 10 минут.
- Независимый mock-исполнитель: одна отправка за раз, сохранение намерения до вызова и результата после, максимум три попытки явно временной ошибки, пауза/остановка. Неизвестный ответ не повторяется.
- Native IndexedDB checkpoint и Web Locks между вкладками; недоступность блокирует запуск. При возврате sent становится unknown, автостарта нет.
- Демо-контекст demo.local/demo-admin: сетевых запросов и изменений Bitrix24 нет. Демо-данные сбрасываются при перезагрузке, последний отчёт сохраняется отдельно.
- Официальный `@bitrix24/b24jssdk` 2.2.0 и узкий read-only шлюз с allowlist: `profile`, `crm.category.list`, `crm.status.list`, `user.get`, `crm.item.list`. В real-режиме транспорт удаления отсутствует.
- Контекст портала/пользователя, права администратора и часовой пояс загружаются до справочников. Документированный профиль без `TIME_ZONE_OFFSET` поддерживается: offset вычисляется по IANA-зоне; пустая зона явно моделируется как недоступная с безопасной UTC-границей.
- Воронки загружаются до конца через offset-страницы `crm.category.list`, чтобы не потерять основную воронку `id=0`; стадии и активные ответственные — через list-helper SDK. Справочники дедуплицируются, CRM-порядок воронок и стадий восстанавливается по `sort`/`SORT`. Зашитых ID стадий нет.
- `crm.item.list` для сделок (`entityTypeId: 2`) собирается курсором, дедуплицируется и прекращается на 3 001-м уникальном ID. Граница дня учитывает IANA-зону и сезонный offset.
- Верхнеуровневый локальный запуск остаётся demo; iframe инициализирует SDK. Ошибка iframe не подменяет данные mock-списком и показывает только безопасное сообщение.
- Real-preview помечен как «только чтение», показывает портал/пользователя и ссылки на карточки, но не показывает подтверждение удаления.

## Проверено локально

- `npm test`: 252 теста в 23 файлах прошли, включая SDK-шлюз, основную воронку `id=0`, документированную форму profile, пустую зону, границы справочников 50/51, runtime-парсеры внешних ответов, строгие CRM datetime, DST, потоковый лимит и iframe-режим.
- Проверка типов, ESLint и Prettier проходят. Production-сборка: 238 модулей, JS 493,32 kB (152,05 kB gzip), CSS 7,74 kB (2,25 kB gzip).
- PHP lint для исходного и собранного входа, `git diff --check` и байтовое совпадение корневых PLAN/PRODUCT с зеркалами прошли.
- Установлена одна прямая runtime-зависимость — официальный SDK 2.2.0; `npm audit` не нашёл уязвимостей при установке. Сохранённый MIT-текст совпадает с пакетом.
- В production-коде адаптера нет mutating CRM-методов или секретных параметров. Bundle содержит ожидаемые маркеры SDK и четыре используемых REST-метода справочников/поиска; встроенные значения токена и webhook-URL не найдены. Имена секретных полей присутствуют только в штатном словаре редактирования SDK.
- Chrome: CSV на 44 выбранные строки; modal на 1 200/700/350 CSS px; Escape и фокус, включая просроченное подтверждение; блокировка фильтров; пауза/стоп; межвкладочный lock; изоляция контекста; прерванный отчёт без автостарта.
- Настоящая IndexedDB: чтение checkpoint второй вкладкой, отказ сохранения при abort после request success. Артефакты: `.superpowers/local-operation-checks/`.
- Независимое ревью: исправлены возврат фокуса и lifecycle при замене сервисов; в read-only адаптере исправлены обязательность недокументированного offset, одностраничные справочники, классификация bootstrap-ошибок и чрезмерно свободный разбор дат.

## Ограничения

- SprintHost, настоящий iframe, scopes, права и ответы REST ещё не проверены. Колонка Bitrix в матрице остаётся НЗ; локальные контрактные тесты не доказывают совместимость конкретного портала.
- Реальный режим намеренно read-only. `crm.item.delete` в его шлюзе запрещён, поэтому реальное удаление, полноценное возобновление, постоянная история и миграции старых схем отсутствуют. Незнакомые checkpoint отклоняются.
- 3 000 ID проверены на mock, не как замер скорости настоящего API/IndexedDB. Полная перезапись checkpoint выбрана для простоты, требует отдельного измерения перед масштабным запуском.
- Проверена текущая версия desktop Chrome. 350 CSS px не заменяет фактический zoom 200 % в iframe.
