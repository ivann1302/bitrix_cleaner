# Продукт — CRM Cleaner

## Цель и первый пользователь

Цель первого цикла — получить первую внешнюю оплату и проверить коммерческий спрос. Первый технический пользователь — Иван и его портал Bitrix24. Первой сущностью выбраны сделки; первая задача — удалить накопившиеся старые проигранные сделки, до 3 000 записей за операцию.

Проверка на своём портале подтверждает удобство и работоспособность. Спрос подтверждает только оплаченный пилот на внешнем портале.

## Состав первого платного MVP

В первом MVP реализуются сделки. Архитектура допускает вторую сущность через конфигурацию, но интерфейс и интеграция лидов не создаются параллельно.

После первой оплаты возвращаются: вторая CRM-сущность, очистка списка чатов, постоянная история, полноценное восстановление операций, расширенная браузерная поддержка и Marketplace. Подготовленные чат-макеты и требования сохраняются как спецификация следующего дополнения.

## Основной сценарий MVP

1. Открыть приложение в Bitrix24 и увидеть текущий портал и тип CRM.
2. Настроить условия и собрать полный список.
3. Увидеть `Найдено`, `Выбрано`, `Исключено` и просмотреть карточки.
4. Исключить нужные записи и скачать CSV перед удалением.
5. Сверить портал, условия и точное количество в отдельном подтверждении.
6. Запустить удаление красной кнопкой `Удалить N записей`.
7. Следить за прогрессом; при необходимости остановить новые запросы.
8. Получить отдельные числа подтверждённых удалений, ошибок и неизвестных исходов.

## Требования первого MVP

| ID | Требование и критерий приёмки |
| --- | --- |
| P01 | Одна выбранная CRM-сущность; портал и пользователь определены до запросов; удаление доступно только администратору |
| P02 | Фильтры даты создания/изменения, ответственного и статуса/стадии; для сделок — воронка. Неприменимые поля не показываются |
| P03 | Даты имеют понятные границы и часовой пояс; дата изменения не называется датой последнего общения |
| P04 | Пустой фильтр, нулевой результат и незавершённый сбор не допускаются к удалению |
| P05 | Список содержит максимум 3 000 ID. При большем числе требуется сузить фильтр; тихого обрезания нет |
| P06 | Preview показывает ID, название, статус/стадию, ответственного и даты и позволяет открыть карточку |
| P07 | Исключение строки меняет точный итоговый набор и счётчик; в строке нет удаления в обход подтверждения |
| P08 | CSV до удаления содержит согласованные поля и безопасно обрабатывает формулы, кавычки, переносы и кириллицу |
| P09 | Подтверждение относится к порталу, сущности, условиям и точному набору ID; изменение списка аннулирует его; контрольной фразы нет |
| P10 | Preview имеет ограниченный срок актуальности, начально 10 минут; после истечения требуется новый сбор |
| P11 | Удаление выполняется небольшими пакетами; результат учитывается отдельно по каждому ID |
| P12 | Пауза/остановка прекращает новые отправки, не обещая отозвать уже отправленные запросы |
| P13 | Ограниченные повторы применяются только к временным ошибкам; потерянный ответ не считается доказанным успехом |
| P14 | Минимальный локальный checkpoint изолирован по порталу и пользователю; токены не сохраняются; при отказе хранилища старт блокируется |
| P15 | После закрытия вкладки нет фонового выполнения или автостарта. При возврате показываем прерывание и предлагаем проверить CRM и собрать новую выборку |

## UX

Принято направление «мягкий бирюзовый минимализм»: тёплый светлый фон, белые поверхности, приглушённый бирюзовый акцент, заметный счётчик и плотная таблица. Красный используется только для кнопки, непосредственно запускающей удаление. Переходы, исключение, пауза и отмена остаются бирюзовыми или нейтральными.

Для первого MVP экран выбора типа не нужен: приложение сразу открывает фильтры выбранной сущности. Многообъектный выбор и чат-экраны из визуальной галереи относятся к этапу расширения.

## Ограничения

Очистка работает в браузере. Закрытие вкладки прекращает новые запросы; уже отправленные могут завершиться. Сон компьютера и фоновая вкладка могут задерживать работу.

Подтверждается фиксированный набор ID, но состояние CRM может измениться после preview. В MVP риск ограничивается коротким сроком актуальности. Повторная проверка контрольных полей каждой карточки возвращается после первой оплаты.

Checkpoint помогает объяснить прерывание, но не обеспечивает полноценное продолжение. CSV не восстанавливает целиком карточки, связи и историю. Обратимость через корзину универсально не обещаем.

## Следующее дополнение после оплаты

Сначала добавляется вторая CRM-сущность. Затем — очистка списка чатов: чтение `im.recent.list`, preview и скрытие подтверждённых `DIALOG_ID` через `im.recent.hide`. Сообщения не удаляются, другие пользователи не затрагиваются, открытые линии требуют отдельной проверки.

После этого возвращаются локальная история, итоговый CSV, IndexedDB с миграциями, полноценное восстановление, расширенная координация вкладок, другие браузеры и Marketplace.

## Ещё нужно решить

- Дата, статусы и остальные условия первой очистки.
- Поддомен/каталог SprintHost и тестовый портал перед внешним размещением.
- Стартовая цена и кандидаты на платный пилот после рабочего preview.

## Приёмка первого MVP

Требования P01–P15 реализованы. Двенадцать блокирующих сценариев из `TEST-MATRIX.md` имеют результаты, read-only работа в реальном iframe подтверждена, разрешённые серии удаления завершены, а известные ограничения опубликованы.

Коммерческая цель закрывается только первой фактической внешней оплатой и обратной связью по выполненной очистке.
